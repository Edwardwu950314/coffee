### 11/11：用感應器編號追蹤豆子，避免重複辨識

討論後的想法：豆子通過第一個感應器時就有編號，被拍照辨識後繼續追蹤並把編號留在該顆豆子上；下一顆豆子觸發感應器進來、前一顆還沒離開畫面時，程式就知道前一顆已經辨識過。

- 把找豆子與追蹤獨立成共用模組 `beans.py`（`find_beans`、`crop_square`、`Track`、`Tracker`），`webcam.py` 與 `bean_classifier.py` 共用
- **追蹤（`Tracker`）**：用「上一次位置 + 速度」預測下一次的位置，再和新偵測到的框做最近距離配對（距離上限 = 1.2 倍豆子邊長）；配對成功沿用編號並更新速度，沒配到的給新編號，連續 3 次沒出現就刪除。輸送帶速度大致固定，所以用速度預測
- **認領（`Vision.claim`）**：背景執行緒持續追蹤；收到 `S,編號` 時，把編號綁到畫面裡「最靠左、還沒有編號」的那一顆（豆子由左到右移動，最左邊的就是剛進來的），只辨識這一顆；結果與壞豆機率存在這顆豆子上
- 認領在主執行緒立刻做，辨識才交給另一個執行緒，確保認領順序和 S 的順序一致
- 收到 S 時若畫面裡還找不到新豆子，最多等 `CLAIM_WAIT_S`（0.3 秒），仍沒有就回傳 BAD 並印出警告
- 預覽畫面：黃框 = 還沒編號，綠框 = GOOD，紅框 = BAD，框上寫感應器編號與壞豆機率，例如 `12 BAD 87%`；終端機也印出壞豆機率
- 原本的 `CAPTURE_DELAY_S` 拿掉，由上面的等待機制取代
- `webcam.py` 同步加入追蹤：每顆豆累積多次壞豆機率取平均（`--samples`，預設 5 次後不再重新辨識），並顯示 `#編號`、累計豆子數；新增 `--max-missed`

#### 程式碼：認領最靠左的新豆子（`bean_classifier.py` 節錄）

```python
def claim(self, bean_id):
    deadline = time.monotonic() + CLAIM_WAIT_S
    while True:
        with self._lock:
            fresh = [t for t in self.tracker.tracks if t.bean_id is None and t.missed == 0]
            if fresh and self._frame is not None:
                track = min(fresh, key=lambda t: t.center[0])  # 由左到右，最靠左的就是剛進來的
                track.bean_id = bean_id
                return track, self._frame.copy(), track.box
        if time.monotonic() >= deadline:
            return None
        time.sleep(0.02)
```

## 三、遇到的問題與檢討

- **以下都還沒有實機驗證**：目前只有語法檢查，以及用模擬的兩顆豆子（一顆往右、一顆往左）測過追蹤編號不會互換。認領、預覽、按鍵與 `webcam.py` 的追蹤，都還沒用真實畫面或 Arduino 跑過
- **追蹤的參數需要實測調整**：
  - `webcam.py` 預設每 0.3 秒偵測一次（`--interval`），輸送帶太快時，兩次偵測之間豆子移動太遠，配對會失敗、編號亂跳，可能要調小
  - 配對距離（1.2 倍豆子邊長）和速度平滑的比例都是預設值
- **追蹤中斷的風險**：已認領的豆子若被追丟，重新偵測時會變成「沒有編號」的新豆子，可能被下一個 S 誤認領。因為取的是最靠左的，通常會選到真正剛進來的那顆，但仍可能出錯
- **其他限制**：
  - `find_beans` 會捨棄碰到畫面邊緣的豆子，所以豆子要完全進到畫面才會被認領，這是 `CLAIM_WAIT_S` 要等待的原因之一
  - 豆子互相貼在一起被當成一塊時，認領會出錯
  - 每幀都要跑 `find_beans`（含 watershed），Orin 上的幀率尚未量測
- **畫面方向假設**：目前假設不旋轉的畫面中豆子由左往右移動；若實際方向不同，要調整 `ROTATE` 或改選「最靠右／最上方」的豆子
